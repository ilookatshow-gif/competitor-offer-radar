# Сравниваем цены, сроки и состав офферов конкурентов

`competitor-offer-radar` — бесплатная локальная CLI-утилита. Вы сохраняете два разрешённых структурированных снимка, программа показывает, что изменилось: стоимость, срок, состав, появление/отсутствие ID. Всё воспроизводится по исходным значениям, URL и времени наблюдения.

Модуль **Lookatshow — единой системы управления маркетингом для ИИ-агентов**. [Все открытые инструменты](https://github.com/ilookatshow-gif/lookatshow-open-tools). Для разбора локальной выгрузки площадок РСЯ есть самостоятельный [direct-report-audit](https://github.com/ilookatshow-gif/direct-report-audit). Покупка ядра не нужна; автоматическая связка модулей не поставляется.

Это не MCP-сервер и не управление сайтами/рекламой. Программа не открывает браузер, не делает запросы, не обходит ограничения и не ранжирует «победителей». Изменение суммы само по себе не доказывает, что оффер стал хуже. Код разработан с помощью ИИ; происхождение и лицензия — в NOTICE.md и LICENSE.

## Быстрый результат

Нужен Python 3.9+; сторонних зависимостей нет. Из распакованного каталога:

```sh
python3 -B competitor_offer_radar.py doctor
python3 -B competitor_offer_radar.py validate examples/before.json
python3 -B competitor_offer_radar.py compare examples/before.json examples/after.json
python3 -B -m unittest discover -s tests -v
```

На учебном `strategy-session` заявленная точная цена меняется с 10 000 до 12 500 RUB за `package`: +2 500 и +25%. Срок — с 4 до 6 рабочих дней: +2 и +50%. Количество интервью — с 2 до 1 `meeting`. `starter` отсутствует в более позднем снимке; `audit` в нём появился. Это наблюдения на выдуманных данных, не результаты клиента. Старый продукт не объявляется закрытым, новый — запущенным. Итоговая оценка ценности, скидок и сопоставимости остаётся человеку.

В этом примере `scope_changed_warning=true`: состав пакета изменился, поэтому +25% нельзя считать чистым подорожанием равнозначного объёма услуг. Неизвестные `quantity`/`unit` компонентов также дают предупреждение `unknown_component_fields`, даже если оба снимка содержат одинаковые null.

## Установка и удаление

Установщик копирует только файлы из `MODULE.json` в **новый** указанный каталог. Не скачивает зависимости, не меняет PATH, agent config или системную политику. Пример для macOS/Linux; выберите своё пустое место:

```sh
python3 -B install.py --prefix ../offer-radar-installed
../offer-radar-installed/bin/competitor-offer-radar doctor
```

При установке из каталога исходника prefix должен быть **снаружи** него: например `../offer-radar-installed`, а не `./offer-radar-installed`. Для команды из любого каталога используйте полный путь к установленному `bin/competitor-offer-radar` либо самостоятельно добавьте этот bin в PATH. На Windows можно использовать `python competitor_offer_radar.py ...` или установленный `bin\competitor-offer-radar.cmd`; Windows-лаунчер предоставлен, но отдельный Windows-прогон не подтверждён.

Установщик не перезаписывает существующий prefix. Если установка оборвалась, сначала осмотрите созданный каталог; не удаляйте другие файлы автоматически. Для удаления переместите именно выбранный каталог установки в корзину. Если вы добавляли bin в PATH или skill в свой агент вручную, удалите только соответствующую запись/копию. Никаких сервисов или фоновых задач не создаётся.

Авторское приветствие даётся только явной командой после установки. Выберите отдельный state-каталог **вне** пакета/каталога установки; повтор с тем же каталогом не выводит рекламу:

```sh
../offer-radar-installed/bin/competitor-offer-radar onboard --state-dir ../offer-radar-state
```

Маркер — локальный файл `competitor-offer-radar-onboard-v1`; никакие сведения не отправляются. Это «один раз на выбранный каталог», а не идентификация человека. Изменение/удаление каталога может повторить приветствие. Обычные doctor/validate/compare никогда его не показывают.

## Контракт снимка

UTF-8 JSON до 2 MB, строго эти поля (лишние поля и дубли JSON-ключей отвергаются):

```json
{
  "schema_version": 1,
  "synthetic": true,
  "captured_at": "2026-10-01T10:00:00+03:00",
  "offers": [{
    "id": "stable-offer-id",
    "name": "Учебный оффер",
    "source_url": "https://example.test/offer",
    "price": {"amount": "10000", "currency": "RUB", "unit": "package", "price_basis": "exact", "tax": "included", "min_order": "1"},
    "delivery": {"value": "4", "unit": "business_days"},
    "components": [{"id": "meeting", "label": "Интервью", "quantity": "2", "unit": "meeting"}]
  }]
}
```

- `captured_at`: ISO-дата с T, секундами и Z либо часовым поясом HH:MM; сравниваются UTC-моменты. Второй снимок строго позже первого. По 2 000 офферов максимум, по 200 компонентов. Одинаковые `id` в разных снимках должны обозначать один и тот же продукт. Программа не выясняет идентичность по названию. Дубли offer/component ID — ошибка.
- `synthetic`: boolean; не смешивайте учебный и реальный снимки. При `true` URL обязан указывать на `example.test`. При `false` берите только данные, которые вправе использовать. URL — http(s), без credentials и fragment; программа сохраняет URL, но не посещает его и не доказывает достоверность источника. Не вставляйте подписанные/секретные URL.
- `price` и `delivery` могут целиком быть `null`: неизвестно. `amount`, `value`, `quantity`, `min_order` — десятичные строки/JSON-числа либо `null`, не boolean. Неотрицательные, без экспоненты, до 16 цифр целой части и 8 после точки. Строки рекомендуются: так ваш редактор не потеряет точность. `min_order` должен быть положительным либо null; это минимальное число **той же единицы оплаты** (для package обычный минимум `1`). Null не означает, что минимума нет.
- Цена сопоставима для арифметического diff только при известных amount/currency/unit/price_basis/tax/min_order и одинаковых условиях. `currency` — три заглавные буквы, не проверка существования валюты. `unit` — ваша согласованная метка, например `hour` или `package`. Другая валюта/единица/минимум/налоги — `not_comparable`, без выдуманной конвертации. `tax`: included/excluded/unknown. `price_basis`: exact/from/null. Цена «от» — лишь нижняя граница; даже две цены «от» дают `not_comparable`, а исходные значения остаются видимы.
- Срок `unit`: calendar_days/business_days/weeks/months/null. Разные единицы не пересчитываются. Неизвестные value/unit дают `not_comparable`. Количество дней — не качество услуги.
- `components`: null — состав неизвестен; пустой список — явно ни одного перечисленного компонента. Компонент содержит стабильный id, label, quantity, unit. Порядок элементов не важен. Изменение названия, количества или единицы показывается как before/after, без сложения несопоставимых единиц и вывода «состав похудел».

Условия вне схемы — скидки, отсрочка платежа, регион, SLA, точная комплектация пакета, юридические/договорные условия, доступность — требуют ручной проверки. Метка `package` сама по себе не гарантирует равнозначность двух пакетов: проверяйте состав. В отчёте цена имеет `pricing_scope="declared_amount_only"`: арифметика относится только к заявленной сумме, не к цене одинакового объёма услуг. При изменённом/неизвестном составе или условиях ставится `scope_changed_warning=true` с причинами. В учебном примере это предупреждение присутствует: +25% — изменение заявленной суммы за изменённый пакет, а не доказательство чистого подорожания эквивалентного пакета. Разные ID не сравниваются по стоимости автоматически. Для анализа рынка нужны несколько наблюдений, не эти два учебных файла.

## JSON и ошибки

Все рабочие команды выводят JSON в stdout; `--help`/`--version` — обычный текст argparse. Ошибки аргументов — stderr и код 2. `doctor`: `ok/version/mode/auth_required/network/telemetry/python`. `validate`: `ok/offer_count/synthetic/captured_at`. `compare`: `ok/schema_version/synthetic/captured_before/captured_after/offers/manual_review_required/limitations`.

В строках common ID: price/delivery имеют `status`, before/after, `absolute_change`, `percent_change`, reasons. Деньги/числа выводятся нормализованными строками, null остаётся null. Абсолютная разница точная; проценты округляются HALF_UP до шести знаков (хвостовые нули удаляются). При нулевой исходной величине процент null с причиной, не Infinity. `components` имеет appeared_ids/absent_later_ids/changed либо not_comparable. Новые/исчезнувшие offer ID: appeared_in_later_snapshot/absent_from_later_snapshot + observed_offer. Все строки требуют ручной оценки; коммерческого вердикта нет.

Ошибочный вход полностью останавливает сравнение: код 2 и `{"ok":false,"error":{"code":"invalid_input","message":"..."}}`. Частичных результатов нет. Код 0 означает успешный локальный расчёт, а не доказанный источник, сэкономленные деньги или успех бизнеса. Читаются только заданные локальные regular files; FIFO/devices не поддерживаются. Результат может содержать исходные сведения: храните реальные отчёты приватно. Никакой рекламы в JSON сравнения.
